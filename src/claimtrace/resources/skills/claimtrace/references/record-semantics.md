# Evidence, review and replay

Use this reference when interpreting a result, recording an observation or
handling an agent proposal.

## Describe what the source establishes

| Source | Recordable observation | Further evidence for a stronger statement |
| --- | --- | --- |
| Native scene expression | A selection, view, representation or requested operation occurs at a source location. | Execution and outputs establish what the original viewer produced. |
| Supplied table or validation report | The supplied record reports a result with its documented settings. | Actual execution records establish a new calculation or independent reproduction. |
| Rendered image | Visible features and their relationship to a stated figure claim. | Source data and settings establish measurements, identity and threshold-dependent interpretations. |
| Tool output produced during this task | The observed result from the recorded inputs, software and settings. | Further analyses establish claims beyond that check. |
| User interpretation | The user's stated meaning, assumptions or judgment. | Linked evidence lets another reader assess its support. |

Preserve exact source selectors and identifiers. Resolve molecule, chain,
residue, atom and model identity from the attached data; record ambiguous
mappings explicitly. A residue label alone may refer to several models or chains.

State that a result was supplied when reading an existing analysis. Use wording
such as “The supplied contact table records…” or “The attached replay log
reports…”. Record a new measurement or successful replay after observing its
actual output.

## Keep three outcomes separate

- **Record completeness:** required links, files and metadata are present for
  the selected package purpose.
- **Scientific review:** a reviewer assesses whether the linked evidence
  supports the exact statement and its limitations.
- **Scene replay:** the original viewer reconstructs the relevant display from
  its inputs and settings, with an observed result or a supplied replay record.

Package validation addresses its declared rules. Describe the validation result
and remaining findings directly. A successful record check leaves scientific
support and viewer replay to their corresponding evidence.

## Attribute agent work

Use the proposal interface for agent-authored additions and changes. Record the
agent's available identity, the request or rationale, the affected claim and
relevant source IDs. Supply model or provider details only when the host actually
exposes them. Keep credentials and unrelated conversation out of the record.

Tie a suggested camera, selection or uncertainty annotation to its source and
purpose. A selection proposal needs the native expression and enough identity
context for a reviewer to locate its target. A warning needs the observation or
missing input that triggered it.

Preserve a proposal's review state until a real review decision occurs. Record
human acceptance with the actual reviewer and decision. Reviewed proposals
retain their decision history, including rejection and reversal. Existing authorization governs
ordinary package operations; it also defines which decisions the user has
actually delegated.

For a new external analysis, preserve the executed command or method, input
artifacts, material parameters, software/version when available, and output
artifacts. Attach only files produced or supplied for the task. Use existing
package integrity mechanisms for file identity.
